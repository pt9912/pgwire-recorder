# Ein Plan über der Grenze ohne Schnitt nimmt keine Sendung an

**Sub-Area:** `*` (gesamtes Repo, Kürzel `REPO`)

Eine Regeländerung (etwa die Schichtzählung) legt einen Plan über die Grenze von drei
Liefer-Punkten oder zwei Schichten. Der Plan nennt den Schnitt als Entscheidung „vor dem
ersten Code-Commit“, statt ihn sofort zu schneiden. Bis dahin ist er als Adresse tot: Eine
Sendung an ihn ließe ihn über der Grenze (`AGENTS.md` §3.13), und sie unterbleibt; der
Geber hält das Risiko offen und der Befund bleibt ohne Eintrag.

Abgrenzung zu `BEO-REPO/slice-waechst-durch-uebernahmen`: Dort wächst ein Slice durch
Sendungen. Hier liegt er schon über der Grenze, und die Sendungen bleiben aus.
