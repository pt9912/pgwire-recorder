**Fund:** `SPEC-067` Punkt 20 (2) legt den Exit-Code des **Skripts** fest (der des ersten scheiternden Schrittes, sonst 0); die Schnittstelle ist das Make-Ziel. Die erste Fassung des Rezepts schrieb daraufhin jeden Code von `docker run` dem Skript im Container zu und meldete bei einem nicht ziehbaren Image `Exit-Code 125 (Code des Skripts im Container, nicht der von make)`, obwohl kein Container lief und 125 der Code der Docker-CLI ist — genau den Weg nennt Punkt 20 (4) (Review F-1, MEDIUM; der Reviewer hat ihn gefahren). Über `make` sieht der Aufrufer ohnehin `2`. Behoben (`8632a78f`): Das Skript nennt seinen eigenen Code als letzte Zeile aus der `EXIT`-Falle, das Rezept unterscheidet `0`, `7` (abgelaufene Grenze des Wartens), `125|126|127` (Docker-CLI) und sonst den Verweis auf die Skript-Zeile; drei Fehlerpfade sind rot gesehen, zwei davon von der Verifikation nachgefahren.
